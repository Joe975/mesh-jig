# Known gaps

- Numeric matching is not a finished visual-quality judgment. Inspect the model, regional closeups and gates.
- Default cameras suit a craft; upright subjects need explicit cameras, height and scoring views.
- Lighting and shaded reference art can shift palette classification. Correct colour storage does not guarantee
  the lit renderer assigns the same named colour.
- An unthresholded review region is an observation. Define quality limits before treating it as acceptance.
- The script checker is a denylist, not a security sandbox. Aliases and indirect calls can evade static checks.
- No general rigging, animation or deformation-quality acceptance workflow is supplied.
- Agent context compaction and recovery policies are configurable; provider reasoning and cost reporting vary.
- Only the implemented renderer determines the numeric result; other engine renderers can look different.
- A project needs suitable reference views. Inconsistent artwork cannot define one exact shared projection.
- A coding agent using the skill and the API visual workflow are not given the same things: the first reads
  its scores, the reference's outline table and as many previews as it likes, the second only pictures and a
  reviewer's notes, one build a round. A difference between their results is not a difference between models.
- The API visual workflow's reviewer sees no earlier review, so its advice on one part can reverse from one
  round to the next.

Keep experimental evidence and personal project records in private version control. Public documentation
describes behavior and limitations without publishing run results.
